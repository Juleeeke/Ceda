# PCB 后布局仿真：开源与商业生态调研

调研日期：2026-10-14。面向 KiCad、macOS、本地优先、个人/小团队、MCU＋传感器＋电源板。

检索覆盖英文与中文、GitHub、项目文档、开源社区线索和商业厂商公开资料；纳入 31 个工具/产品家族，其中开源及公开项目 17 项、商业/免费闭源方案 14 项。列表是有边界的广泛调研，不声称穷尽所有项目。

能力来自下列项目/厂商的一手资料。本次未安装、运行、源码审计或实测精度；“推荐评估”是本方案的判断。官网中的“高精度”“完整”“自动”等宣传词不作为独立验证结论。商业价格、完整授权范围、macOS 支持、KiCad 直读及自动化 API，未有明确证据处均需另行确认。

## 1. 开源、公开项目和可复用基础

“可复用基础”不等于支持直接导入 KiCad；“有插件”也不等于有完整物理验证。

## 2. 与本项目最相关的四个社区项目

### padne

它直接把 KiCad 几何与集总源/负载连接起来，2.5D FEM、供电端与回流端的配置方式尤其值得研究。需要验证：当前 KiCad 兼容、macOS 构建、实际铺铜/热焊盘/过孔导入、端口约束、收敛、数值与实测精度。项目存在测试目录本身不代表这些验证都已完成。[项目来源](https://github.com/atx/padne)

### KiPIDA

多级电源树、源/负载到焊盘的映射和板上结果有较强产品参考价值。项目自述处于 Alpha；应分开核查 DC、电热和未来 AC/完整热功能，不能将路线图全部计入当前功能。[项目来源](https://github.com/kbralten/KiPIDA)

### KiCad Thermal Sim

适合学习分层热网络、铜分布、过孔增强、对流与功率波形的交互。其现有说明强调铜层扩散和局部边界，并明确有限制。不要把输出板温等同于精确芯片结温。[项目来源](https://github.com/PoeAlex/KiCad_Thermal_Sim)

### z_extractor

价值在“布局→寄生模型→电路/电磁求解”链路。README 对模型误差的警示使它更适合作为待改进参考，而不是拿来支撑准确性优先产品的承诺。[项目来源](https://github.com/liuanlin-mx/z_extractor)

## 4. 未纳入核心候选的相邻方向

- [RedSIM AUTO](https://www.rededa.com/redsim-auto/)：公开页面将其定位于 PCB/多物理场仿真自动化，可借鉴流程；本次未核实其底层求解器依赖，不计作独立开源求解内核。
- [Xpeedic Metis](https://www.xpeedic.com/index.php?a=show&c=index&catid=133&id=28288&m=content)：官方重点在 2.5D/3DIC、Chiplet 和先进封装，与首版 MCU/传感器板不同，保留为相邻产品参考。
- Gitee 检索发现 KiCad 相关入口，但本次未核实到满足完整目标的独立项目，因此不为增加数量而列入“可用整板仿真产品”。
- AI 审图、自动 DRC、自动布线、3D 渲染及规则化载流计算可用于辅助，不能直接替代受材料、激励和边界条件约束的物理求解。

## 5. 开源属性与集成注意点

本次从项目页面核实的许可证标识：KiPIDA 为 AGPL-3.0，padne 为 GPL-3.0，KiCad Thermal Sim 为 MIT，z_extractor 为 Apache-2.0，openEMS 为 GPLv3；Gmsh 官方说明为 GPL v2 或以后版本并含例外。ngspice 官方说明主要为修改版 BSD，但包含例外组件。[ngspice 说明](https://ngspice.sourceforge.io/devel.html)、[openEMS README](https://github.com/thliebig/openEMS/blob/master/README.md)

这是初筛记录，分发前仍应按锁定版本检查 LICENSE、第三方依赖和模型条款。不能因为顶层项目开源，就推断所有捆绑库、厂商模型和 GUI 都具有相同许可；也不能仅因为采用独立进程就断言所有许可问题都已解决。

## 6. 建议的短名单与下一步评估顺序

1. KiCad IPC/文件适配＋ngspice：先证明真实布局与电路节点可以正确连接。
2. padne 与 Gmsh＋GetDP：使用相同标杆比较几何保真、DC 结果、维护成本和 macOS 可用性，再选 DC 路线。
3. GetDP 热场与 Elmer：在有边界数据的板级算例上比较；KiCad Thermal Sim 作为轻量对照。
4. FastHenry2＋FasterCap：评估关键互连的 RLC 提取和一致的多端口边界。
5. openEMS＋scikit-rf：针对准静态模型不够用的结构引入，避免提前扩大第一版范围。
6. Renode：在电气联合链路可信后，再评估具体 MCU、外设和时间同步。

评价维度统一为：导入保真、模型覆盖、解析/实验精度、收敛诊断、macOS 可用性、可自动化接口、许可证、文档与维护、实际资源消耗。没有测试数据的维度填写“待验证”，不采用主观总分排名。

总体判断：可复用的开源求解器很多，针对 KiCad 的局部能力也已出现；真正待建设的是可追溯的统一板卡模型、端口映射、模型管理、工况编排、电热/电路耦合和系统级验收。这也是新软件应集中投入的部分。
